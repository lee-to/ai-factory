# Архитектура AI Factory

AI Factory — модульный монолит. CLI, установка навыков, преобразование форматов и конфигурация MCP поставляются в одном npm-пакете и развиваются в рамках одной версии. Внутри пакета команды, основная логика и общие утилиты разделены на модули.

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `src/cli/` | Регистрация команд, разбор параметров, интерактивные вопросы и обработчики |
| `src/core/` | Установка навыков, реестр агентов, конфигурация MCP, расширения и исполнение workflow |
| `src/utils/` | Общие утилиты без привязки к CLI или конкретному runtime |
| `skills/` | Исходники встроенных навыков, их справочные материалы, примеры и вспомогательные скрипты |
| `subagents/`, `mcp/` | Встроенные файлы агентов и шаблоны MCP |
| `scripts/` | Проверки репозитория, навыков и сценариев исполнения |
| `docs/`, `README.md` | Тематические руководства и главная страница проекта |
| `bin/`, `dist/` | Запуск CLI и скомпилированные файлы |

## Границы модулей

Направление зависимостей — `src/cli → src/core → src/utils`. CLI может напрямую использовать общие утилиты. `src/core` не зависит от CLI, а `src/utils` не зависит от двух верхних слоёв. Утилиты должны оставаться независимыми от фреймворков и иметь минимум зависимостей.

Обработчики CLI собирают входные данные и делегируют работу основным модулям через явные интерфейсы. Оркестрация установки и MCP остаётся в `src/core`. Поведение конкретного runtime изолировано в адаптерах, которые выбираются через реестр трансформеров. Трансформеры зависят от контрактов трансформации, а расширения подключаются через выделенные интерфейсы.

`skills/` — канонический источник встроенных навыков. Установщик копирует и преобразует их с учётом выбранного runtime. Runtime-код читает и копирует содержимое каталогов `skills/`, `docs/` и `mcp/`. Сами эти материалы не импортируют runtime-модули. Файлы `dist/` генерируются при сборке. Их нельзя редактировать вручную или импортировать обратно из `src/`.

- **Каталог команд и worktree.** Каталог читает декларации в установленных пределах, сохраняет хеши источников и идентичность директорий. Неоднозначные входы остаются неразрешёнными. Команды расширений не загружаются даже при вызове справки. Диагностика worktree сравнивает ограниченные статические данные, оставляет изоляцию неподтверждённой, не запускает окружения и не меняет сопоставления ресурсов. Создание worktree само по себе не разрешает использовать общие ресурсы.
- **Swarm.** Использование явно включается пользователем. Runtime владеет состоянием и Git-ресурсами `aif/swarm/*`, пользователь владеет `.ai-factory/swarm.yaml`. SQLite и PostgreSQL используют общую логику планирования с установленными лимитами. Handoff использует API и события. Промежуточная интеграция требует пройденных проверок, родительские задачи ждут дочерние, а финальное завершение требует независимой проверки и ревью владельца. Worktree не обеспечивает изоляцию среды. Неопределённость в учёте расхода ресурсов нужно сохранять явно.
- **Dispatch.** Пользовательская конфигурация находится в `.ai-factory.json`. Команды используют шаблоны argv, prompt передаётся одним аргументом. Loop выбирает дальнейший маршрут по версионированному результату. Вывод дочернего процесса для этого не используется. При возобновлении ручной передачи фазы не отправляйте её повторно. Очистите состояние передачи после принятия результата. Тайм-ауты, тихие no-op и fallback описаны в справочных разделах выше.
- **Completion Hook.** Адаптер пишет только принадлежащую ему локальную запись проекта либо ограниченные записи попыток и результатов. Он фиксирует спецификацию, исполняемый файл, входы, рабочий каталог и исходную ревизию. Локальные записи могут подтверждать наблюдаемое выполнение и актуальность, но сами по себе не доказывают подлинность или способность среды гарантированно остановиться при сбое.
- **Записи об инструкциях.** Они создаются только по явному запросу. Декларации ресурсов и переданные вызывающей стороной наблюдения о загрузке не доказывают полную видимость runtime. Неполные запуски остаются явно отмеченными. Учёт бюджета не обрезает инструкции. Только команда `instructions` владеет записями запусков и снимками.
- **Общие навыки.** При `init --symlinks` используйте общие каталоги только для побайтово одинаковых навыков с подтверждённым происхождением. Сохраняйте нативные пути, профили рендеринга и метаданные `useSymlinks` / `skillSymlinks`. До изменения под блокировкой материализуйте зарегистрированные ссылки и восстановите ссылки после успеха. Сохраняйте неотслеживаемые ссылки и общие каталоги без подтверждённого происхождения. `init --no-symlinks` восстанавливает копии.
- **Установка и Devin Desktop.** Выбор `aif` включает управляемую зависимость `aif-skill-generator` для сканирования и очистки заблокированных навыков. Обновление восстанавливает её в старых установках, где она отсутствует. Остальные навыки независимы. Devin Desktop использует ID `windsurf` и `.devin/skills/` для новых установок. Для старых и пользовательских путей применяется сохранённый профиль рендеринга Windsurf. Очистка поддерживает `.devin/skills` и `.windsurf/skills`.
- **Права инструментов.** Формируйте `toolPermissions` только из деклараций для конкретного навыка и runtime. Сейчас нативный адаптер есть у Claude Code. Для остальных runtime выдавайте предупреждение и пропускайте запросы. Сохраняйте принадлежность запросов в записях и при миграции. Запрещено выводить разрешения из свободного текста или расширять запрошенные права. Связывайте исходные права с применённым источником навыка и нативной декларацией. При удалении замены или изменении defaults берите текущее поле источника и заново объединяйте оставшиеся запросы, чтобы прежние права не остались без владельца.
- **Агенты loop.** Встроенные файлы `loop-*` требуют выбранного `aif-loop` в Claude и Codex. При init/update, включая force, пропускайте их при отсутствии навыка и удаляйте ранее управляемые файлы loop и их записи. Сохраняйте файлы пользователя и вспомогательные файлы расширений. Остальные файлы агентов независимы. Фильтр применяется при установке. Инвентаризация учитывает все файлы. В текущей поставке Codex нет ролей loop. Smoke-тесты используют изолированные Markdown- и TOML-фикстуры.
