# Installed Library Audit Report Contract

Use configured language for prose, preserving **observed**, **reconstructed**,
**not measured**, **not checked**, **unknown**, and **blocked recommendation** labels.

## 1. Final Composition

Lead with consequential composition findings and recommendations, including dependencies.
State date, runtimes, roots, installed vs source-only scope, and coverage limitations.

| Scenario / runtime | Active entry and layers in order | Conditions / precedence evidence | Size and method | Observed or reconstructed | Finding / recommendation |
|---|---|---|---|---|---|

Separate discovery metadata, body already including injections, applicable rules,
and conditional references. Show comparable base-to-final growth or unknown.
Include a composed scenario if injections/overrides exist, or explain why unavailable.

## 2. Scope and Inventory

| ID / runtime | Name / path / origin / identity | Eligibility / duties / tools | Layers / dependencies | Read coverage | Usage / outcomes |
|---|---|---|---|---|---|

List missing, unread, inaccessible and shadowed entries, retaining shared runtime
exposures. Usage evidence needs source/window/sample/limits; otherwise not measured.
Unknown is not zero usage, even when no unique duty was found statically.

## 3. Findings and Recommendations

For each finding include ID/dimension/skill IDs/runtime; source sections or lines
and short supporting passages/measurements; triggering request/condition and impact;
confidence (high/medium/low) and observed vs static-inference basis; proposed owner/
location/action, final-composition consequence and verification before applying.

Cover all six dimensions. Distinguish checked with no supported finding from
not checked. Keep outcomes can explain justified specialization or standalone guards.

## 4. Dependencies and Duty Coverage

| From | To | Type / required or optional | Condition | Evidence | Consequence of change |
|---|---|---|---|---|---|

For every merge/removal candidate:

| Candidate | Duty / output / guard | Surviving owner + evidence | Affected callers / injections / consumers | Rewrites / verification | Gaps / decision |
|---|---|---|---|---|---|

Illustrative example, not a real finding: release skills share formatting, but only
one produces a signing receipt. Moving formatting does not cover signing; removal
is a blocked recommendation until a surviving owner and receipt consumers are accounted for.

## 5. Link and Command Verification

| Source / reference | Local evidence or official URL + version | Method / date | Result | Replacement + evidence |
|---|---|---|---|---|

Distinguish valid, verified stale, not checked, and unknown. Network errors do not
prove broken references. No command execution is implied.

## 6. Prioritized Next Steps and Limits

Give concrete ordered recommendations with finding IDs, benefits, dependency work
and verification needed. Separate supported actions from observations/evaluations
still required. End with coverage gaps, usage not measured, unperformed external
checks, and the saved path if any. State that audited inputs were unchanged.
